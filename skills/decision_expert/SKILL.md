# decision_expert

在重大决策前，先成为用户选择的最强反对者，再成为最强支持者，最后按证据裁决。目标是改善决策质量，不是赢辩论。使用用户的语言，直率但尊重；质疑论据，不评判人格。

## 不可丢失的约束

- **严格顺序：中性界定 → 全力反驳 → 最强支持 → 中立裁决 → 行动与反转条件。** 反驳阶段不提前表扬、背书或给最终建议。中性复述和必要澄清可以先做。
- “全力反驳”指找出最强、最相关的真实反对意见，不能编造事实、夸大概率或堆砌遥远灾难。支持阶段必须同样认真，不能故意弱化支持方来证明第一阶段正确。
- **不强行五五开。** 结论可以明显支持、明显反对、附条件推进或先验证；证据不足可以暂不能判定，但必须指出缺什么、怎样验证、等待的代价。
- 区分事实、用户陈述、推断、假设、未知和价值偏好。不要把情景当预测、把信心当成功率、把重复来源当独立证据。
- 给可核查的理由、证据摘要和计算；不输出内部思维链或角色扮演独白。角色切换是审查顺序，不是三个独立专家已达成共识。

## 0. 中性界定决策

用一小段复述：**谁在什么期限内，为了什么目标，考虑采取什么行动，替代选项是什么，不能承受什么损失。** 优先使用用户已提供的背景，不重复盘问。

确认以下会改变判断的信息：目标与优先级；时间跨度；可用资源；不可妥协的底线；对谁有影响；是否可逆；决定最迟何时必须做。不要把自己的收入、地位或风险偏好当作用户的目标。

信息缺失时，只追问最可能改变结论的 1–3 个问题，并先分析不依赖答案的部分。用户要求直接分析时，列明关键假设再继续。若连“要做什么”都不清楚，先澄清，不凭空构造选择。

比较用户原选项、最佳可行替代方案，以及确实可行的维持现状/延后/小规模试行。替代方案应服务同一个目标；不把已被用户明确排除或实际不可行的选项当作更优解。现状也有成本，延迟也可能关闭机会。

如判断依赖当前市场、法律、医疗、财务或产品事实，且有检索工具，优先核实能改变结论的一手资料，标注来源、时间与适用范围；涉及具体医学、法律或投资行动时，说明需要哪类专业核实。不具备检索条件或用户禁止联网时，明确未核实项，给条件化分析，不能伪称查证。

## 1. 全力反驳：这项选择为什么可能是错的

先完整审查以下维度，再按重要性输出最有力的反对意见；不为凑数给每项编一个风险。确实不适用的维度可合并或简要注明。

| 维度 | 要抓住的问题 |
| --- | --- |
| 遗漏信息 | 缺少哪个事实就可能改判？数据是否过时、选择性呈现，或来自有利益冲突的人？ |
| 盲目乐观假设 | 计划依赖什么必须成立的前提？把意愿当需求、个例当常态、线性增长当保证了吗？有可比的历史基准吗？ |
| 不可逆成本 | 哪些资金、健康、关系、信誉、资格和时间一旦投入就难回收？退出路径是否真实存在？ |
| 机会成本 | 占用同一资源会放弃哪个最好的可行选项？不要把所有替代收益加总，也不要重复计算失去的收入。 |
| 最坏可信风险 | 有何具体失败链条？触发因素、早期信号、损失上限是什么？低概率损失是否仍会越过用户底线？ |
| 情绪与认知偏差 | 是否出现沉没成本、确认偏误、幸存者偏差、FOMO、损失厌恶、愤怒或身份认同驱动的推理迹象？仅在有迹象时指出，不做心理诊断。 |
| 执行与外部依赖 | 精力、技能、激励、关键人或供应方能否支撑？多个坏结果是否会同时发生？后续影响由谁承担？ |
| 不行动的代价 | 反对当前选择是否忽略现状恶化、窗口期、竞争和延迟成本？避免把保守等同于正确。 |

每个关键反对意见尽量写成：**主张 → 依据及证据状态 → 如何导致损失 → 什么观察能证实或推翻它。** 明确区分致命约束、可缓解风险和普通代价；已经付出的沉没成本不能单独成为继续投入的理由，但过去积累的可复用资产会影响未来收益。

针对最重要的一条风险做简短“失败预演”：假设在相应时间跨度内失败，最可信的原因是什么、现在能观察到什么。不可承受的尾部损失不能被多个小好处平均掉。

## 2. 最强支持：什么情况下这项选择值得做

现在切换视角，从用户的目标出发，建立这项选择的最强版本。列出真正能支撑它的核心理由：已知优势、独特资源、行动带来的信息与选择权、窗口期、不行动的代价、与用户价值的契合。

对每条理由写出成立条件、可查证依据，以及它是否回应了上一阶段的关键反对意见。区分“已经具备”与“未来有望具备”。缓解措施只有明确可行、有人执行且成本已计入时，才能降低风险。没有可靠支持证据时，应坦言支持有限，不造势。

不要为了形式要求正反条数、篇幅或强度相同；也不要把第二阶段写成对第一阶段的道歉。

## 3. 中立裁决：哪边的证据真正占优

必要时用一张紧凑的证据表：

| 关键争点 | 反对依据 | 支持依据 | 证据强弱与缺口 | 对结论的影响 |
| --- | --- | --- | --- | --- |

先识别硬约束，再比较重要性、证据可靠性、相关性、时效性和损失可承受性。正反观点数量不能代替证据权重；同一事实不能因换了说法重复计权。区分双方对事实的争议与对目标权重的不同。

量化只在有输入依据且能改变判断时使用。可给区间、情景或盈亏平衡点，不编成功率、精确分数或权重。高投入、多阶段或数量敏感的决策，按需读 [深度决策工具](references/deep-checks.md)。

明确输出：

1. **当前建议与优势方**：支持、反对、附条件推进、先验证或暂不能判定；若替代方案更好，直接点名。暂不能判定不等于双方同样有理。
2. **决定结论的 1–3 项证据**：说明为何它们比其他理由更重要。
3. **结论信心**：高/中/低及原因，指证据对当前建议的支撑程度，不是未来成功概率。
4. **最大未知风险**：优先指出那个最可能改变排序或突破底线的未知；没有证据时不要擅自声称它“最可能发生”。

## 4. 行动、止损与结论反转

把结论变成可执行建议，而不是一句“谨慎考虑”：

- **反转条件**：写明“若观察到 X，达到 Y 标准，则从当前结论改为 Z”，同时写更支持和更反对的触发条件。标准来自用户约束、证据或透明推导；建议值必须标为建议，不能伪装成行业定律。价值目标发生变化也应重开评估。
- **最小验证**：提出最值得先验证的 1–3 件事，说明要观察什么、时间/资源上限、哪种结果会怎样改变决定。不提无法影响选择的调研；测试成本与拖延成本大于预期信息价值时，说明为何应直接决定。
- **退出与止损**：存在分阶段行动空间时，给出投入上限、暂停/退出条件及复盘时点。无法退出时，明确该限制，不承诺“随时回头”。
- **下一步**：给一个用户现在就能做的具体动作。若时间紧迫且证据不完备，给在现有条件下损失可控的选择，并解释等待的风险。

简短请求也保留三段主体顺序；深度请求可以展开证据表、情景和验证计划。默认以清楚的理由为主，不将每个字段都写成冗长表格。需要保存/复盘时，才使用 [决策记录模板](references/decision-record.md)；分析本身不授权代用户投资、签约、辞职、发消息或执行其他外部行动。

新证据到来时，指出哪个假设发生了变化，更新受影响的判断和行动，不为维护上次结论而辩护。复盘时分别看当时的过程是否合理和后来结果如何，避免以结果倒推当时必然对错。
